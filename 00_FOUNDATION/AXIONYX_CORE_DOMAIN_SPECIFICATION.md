# AXIONYX Core Domain Specification

**Document Type:** Core Architectural Truth
**Status:** Active
**Layer:** Platform Foundation

This specification bridges the AXIONYX Constitution, the IP Governance Protocol, and the Capability Curriculum into an immutable software reality. The entities defined herein act as the strict ontological map for the entire ecosystem.

## 1. The Core Loop
The AXIONYX machine revolves around a single, unbroken chronological sequence:
`Human → Identity → Mission → Project → Evidence → Capability → Graduation`

## 2. Entity Definitions

### Identity
The unique digital passport of an individual. It aggregates their roles (Student, Mentor, Entrepreneur) and tracks the expansion of their capabilities over time.

### Mission
The existential reason for work. Before any code is written or business launched, a Learner defines the Domain (e.g., Mining, Healthcare) and the Problem they intend to solve.

### Capability
A verified unit of human ability. Moving from `EXPLORER` to `CREATOR`, capabilities are unlocked only upon the systemic validation of raw Evidence.

### Project
The sandbox. A container where the Learner builds an Artifact (e.g., CoalAssist AI). It holds status (Idea → Production) and contributors.

### Evidence
The AXIONYX differentiator. Code, video, documentation, or deployment metrics proving that capability exists. 

### IP Asset
The commercial wrapper. Once a Project hits Production, it is registered here to codify the exact ownership split (e.g., 70% Creator / 30% Ecosystem).

### Revenue Event
The economic outcome. Every time a customer pays for a license, the transaction triggers the split mechanism, injecting wealth back into the creator and sustaining the Ecosystem infrastructure.

## 3. The Kernel (Ecosystem Rules)
To prevent drift, the core business rules (`CanProjectGraduate`, `CalculateRoyalty`, `ValidateEvidence`) are strictly abstracted into the AXIONYX Kernel. Applications cannot override these physics.
